Feature/Flow to test: $ARGUMENTS

1. อ่านโค้ดที่เกี่ยวข้องเพื่อเข้าใจว่า logic ปัจจุบันทำงานยังไง
2. ถามผมก่อนถ้า expected behavior ไม่ชัด อย่าเดาเอง
3. สร้าง test case ที่ครอบคลุม:
   - กรณีปกติ (happy path)
   - ค่าขอบ (boundary: ค่าต่ำสุด/สูงสุดของช่วงปกติ-ผิดปกติ)
   - ค่าผิดปกติ/ไม่คาดคิด (null, string ผิด type, ค่าติดลบ)
4. รัน test จริงแล้วเทียบผลลัพธ์ที่ได้ กับผลลัพธ์ที่ "ควรจะเป็น" ตามที่ระบุ
5. รายงานเป็นตาราง: input → ผลที่ได้จริง → ผลที่ควรได้ → ตรงกันไหม
6. ยังไม่ต้องแก้โค้ด รายงานผลก่อน
